🌱 Seed ข้อมูลทดสอบ (Admin เท่านั้น)

เนื่องจาก Metrics ต้องการข้อมูล Interaction จาก User หลายคน ปุ่มด้านล่างจะ สร้างข้อมูลสังเคราะห์ จาก User และ Device จริงในระบบ โดยจำลองรูปแบบการใช้งานแบบมีกลุ่ม Preference เพื่อให้เห็นค่า Metrics ที่มีความหมาย
?clear=true จะลบ DeviceEvent ทั้งหมดก่อน แล้ว Seed ใหม่

วิธีประเมิน (Temporal Split): ข้อมูล Interaction ที่เก่ากว่า 14 วัน = Training | ข้อมูลใน 14 วันล่าสุด = Test
สำหรับแต่ละ User ใน Test Set: สร้าง Ranking จาก Training แล้วตรวจว่า Device ที่ User จริงๆ Interact ปรากฏใน Top-10 หรือไม่ → คำนวณ Metrics

🔍 วิธีอ่านค่า Metrics

Precision@K

ในบรรดา K รายการที่แนะนำ มีกี่รายการที่ User ชอบจริง? ยิ่งสูงยิ่งดี เพราะหมายความว่าสิ่งที่แนะนำส่วนใหญ่ตรงใจ

≤ 0.10 ต่ำ 0.10–0.25 พอใช้ 0.25–0.40 ดี > 0.40 ดีมาก

Recall@K

จาก Device ทั้งหมดที่ User ชอบ โมเดลดึงขึ้น Top-K ได้กี่เปอร์เซ็นต์? สำคัญเมื่อ Dataset มี Item เยอะ

≤ 0.15 ต่ำ 0.15–0.35 พอใช้ 0.35–0.55 ดี > 0.55 ดีมาก

MRR (Mean Reciprocal Rank)

อยู่อันดับ 1 ได้คะแนน 1.0 อันดับ 2 ได้ 0.5 อันดับ 3 ได้ 0.33 และลดหลั่นไป วัดว่า Item ที่ตรงใจปรากฏเร็วแค่ไหน

≤ 0.10 ต่ำ 0.10–0.30 พอใช้ 0.30–0.50 ดี > 0.50 ดีมาก

MAP (Mean Average Precision)

เฉลี่ย Average Precision ทุก User คำนึงทั้งความแม่นยำและลำดับ ของที่ตรงใจควรกระจุกอยู่ด้านบน

≤ 0.10 ต่ำ 0.10–0.25 พอใช้ 0.25–0.45 ดี > 0.45 ดีมาก

NDCG@K ⭐ (นิยมที่สุด)

Normalized DCG คะแนนรวมหักส่วนลดตามลำดับ แล้วหารด้วยคะแนนในกรณีเรียงสมบูรณ์ ค่า 1.0 = เรียงสมบูรณ์แบบ ค่า 0 = พลาดทุกอย่าง

≤ 0.15 ต่ำ 0.15–0.35 พอใช้ 0.35–0.55 ดี > 0.55 ดีมาก
